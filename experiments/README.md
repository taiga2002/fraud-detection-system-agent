# Experiments Directory

All contents are **regenerated** by `./run_all.sh` (except `shinkaevolve/results*` which require Ollama).

## Directory Structure

### `fusion/` — Step 2 Trained Models

Trained ML model artifacts from the three-layer fusion system:

| File | What | Trained By |
|------|------|-----------|
| `account_risk_model.pkl` | LightGBM classifier for account-level risk (ROC AUC 0.975) | `src/models/account_risk_model.py` |
| `transfer_risk_model.pkl` | LightGBM classifier for transaction-level risk (ROC AUC 0.9999) | `src/models/transfer_risk_model.py` |
| `mule_network_detector.pkl` | NetworkX graph analytics for mule network detection | `src/graph/mule_network_detector.py` |

These are loaded by the fusion evaluation (`src/evaluation/fusion_evaluation.py`) and evolved evaluation (`src/evaluation/evolved_evaluation.py`) to score transactions.

### `shinka/` — Step 3 Optimized Configuration (Optuna)

Output of Bayesian optimization (Optuna TPE sampler) that finds optimal fusion weights and decision threshold:

| File | What | Generated By |
|------|------|-------------|
| `evolved_config.pkl` | Optimized fusion weights + threshold | `src/simulation/simple_evolution.py` |

**Contents of `evolved_config.pkl`:**
```python
{
    'account_weight':  0.184,   # How much to weight account risk (was 0.25)
    'transfer_weight': 0.460,   # How much to weight transfer risk (was 0.45)
    'network_weight':  0.355,   # How much to weight network risk (was 0.30)
    'threshold':       0.579    # Flag if fused score >= this (was 0.30)
}
```

The three weights sum to 1.0 and control how much each risk layer contributes to the final decision. The threshold determines the cutoff for flagging a transaction as suspicious. The fusion layer (`src/scoring/fusion_layer.py`) loads these weights automatically at runtime.

**What Optuna found:** Network risk deserves more weight than the hand-tuned default (0.30→0.355), and a much higher threshold (0.30→0.579) dramatically reduces false positives while maintaining recall. Converged at trial 10 out of 100.

### `shinkaevolve/` — ShinkaEvolve LLM-Guided Evolution

The full ShinkaEvolve experiment using `shinka-evolve` framework with Ollama. See `experiments/shinkaevolve/` for its own files and `docs/shinkaevolve.md` for detailed documentation.

| Directory | What |
|-----------|------|
| `results/` | Easy task run (20 generations) — baseline comparison |
| `results_hardened/` | Hardened task run (20 generations) — +21.2% improvement |

These require Ollama with `qwen2.5:14b` to regenerate and are **not** regenerated by `./run_all.sh`.

## Naming Note

`shinka/` (Step 3, Optuna) and `shinkaevolve/` (LLM-guided evolution) are different systems:
- **`shinka/`** = Bayesian optimization (Optuna) tuning 4 numbers (weights + threshold)
- **`shinkaevolve/`** = LLM evolving code (features, hyperparameters, fusion logic)
