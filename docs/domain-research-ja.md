# 日本向けオンラインバンキング詐欺検知

**テーマ:** オンラインバンキング詐欺に対する受け皿口座・不審送金検知  
**用途:** ShinkaEvolve / AI Scientist を用いた今後の実装に向けた高レベルの問題設定メモ

> **プロジェクト仮説。** 日本の金融機関向けに、オンラインバンキング詐欺における「不正口座開設・IB有効化」「不審送金」「受け皿口座ネットワーク」を一体で検知する適応型エンジンは、Sakana AI にとって有力なテーマである。被害規模が大きく、評価指標を置きやすく、攻撃側の手口変化も速いため、静的な手作業ルールよりも、ShinkaEvolve のように検知シナリオ自体を探索・改善するアプローチと相性がよい。

## なぜこの課題に取り組むべきか

| シグナル | 日本の根拠 | 意味 |
| --- | --- | --- |
| 特殊詐欺の高額被害がインターネットバンキングにシフトしている | 警察庁は、2024年1-5月の被害額500万円以上の振込型特殊詐欺の調査で、インターネットバンキング利用が**被害額の約6割**を占めると公表している。また、**約7割**がすでにIB設定済みの**既存口座**であり、被疑者の指示で被害者がIB口座を開設したり、IB機能を追加設定したりする事例もあるとしている。 [1] | 被害は ATM や店頭で止めやすい従来型の流れから、非対面・高額・高速な送金フローへ移っている。したがって、取引監視だけでなく、口座開設や IB 有効化の段階も含めて見る必要がある。 |
| 金融機関にとっても損失・負荷が大きい | 金融庁によれば、インターネットバンキングによる預金等不正払戻し件数は **2022年度 1,712件 → 2023年度 5,556件 → 2024年度 11,009件** と増加している。**2025年度上半期（4-9月）**でも **1,894件** あり、**1件当たり平均被害額は226万円**に上昇した。さらに、2024年度発生分のうち処理方針決定済みの件数では、金融機関が **10,252件中 8,703件（84.9%）** を補償している。 [2] | これは利用者被害だけではなく、金融機関側の補償コスト、調査・対応工数、レピュテーションリスクにも直結する。 |
| 規制・監督上の要請が明確 | 2025年9月、金融庁と警察庁は連名で、口座開設時対策、多層的検知、シナリオ・敷居値の精緻化、確認・凍結の迅速化、金融機関間の情報共有などの強化を要請した。さらに金融庁の2025年6月フォローアップでは、本人確認方法に応じた真正性確認の仕組みを実装済みとした先は **30%**、不正利用口座と同一の端末・アクセス環境の検知は **46%**、顧客申告情報や過去アクセスと整合しない接続の検知は **29%** にとどまった。 [3][4] | 「もっと精緻な検知ロジック」「より速い遮断」「説明可能な有効性検証」が求められており、実運用に接続しやすいテーマである。 |

直近の警察庁データでも、IB が被害の中心チャネルになりつつあることが確認できる。**2025年上半期**の特殊詐欺被害額は **597.3億円** に達し、その中でも急増している**ニセ警察詐欺**では、**インターネットバンキング利用による被害額が176.2億円**と、同類型全体の**45.2%**を占めた。受け皿口座と不審送金を止められれば、全体被害額に対して大きなインパクトを持ちうる。 [5]

日本の報道もこの傾向と整合している。FNN は富山県の事例として、検察官を名乗る人物らに誘導されて70代男性が複数のインターネットバンキング口座を開設し、**約1億8100万円**をだまし取られた事例を報じている。同記事では、県内で IB を利用した特殊詐欺が **18件**、被害額が **4億6000万円超**、**前年の16倍** に拡大しているとも報じられている。全国統計ではないが、被害者自身に口座を作らせ、送金させるタイプの詐欺が、従来の固定ルールでは捉えにくいことをよく示している。 [6]

## なぜ Sakana AI / ShinkaEvolve に向いているか

銀行の不正検知は、手作業で作られたシナリオが中心で、口座開設審査、取引モニタリング、凍結判断が分断されがちである。この課題は、一般的な LLM アシスタントよりも、**検知ロジックそのものを探索できること**、**攻撃者の行動変化に追随できること**、**複数目的（防止金額、誤検知、審査負荷、顧客負担、凍結までの時間）を同時に最適化できること**、そして**監督・監査に耐える説明可能性を保てること**が重要であり、Sakana AI 型のアプローチに適している。

また、金融庁は2025年に、マネロン等対策について「態勢を作ったか」だけでなく、**実際に有効に機能しているかを検証し説明できるか**という「有効性検証」に重心を移している。したがって、監査可能でテスト可能な検知システムの価値は今後さらに高まる。 [7]

言い換えると、狙うべき研究課題は単なる「不正予測モデル」ではなく、**より良い検知・介入プログラムを自動的に発見すること**である。

## 高レベルの実装アイデア

1. **課題を3つの連結タスクとして捉える。**  
   (a) 不正口座開設・IB有効化、(b) 不審送金検知、(c) 受け皿口座ネットワーク検知を一体で扱う。日本の事例では、実際の送金前から不正の兆候が始まっている。

2. **グラフ中心の表現を使う。**  
   顧客、口座、受取人、端末、IP・アクセス環境、電話番号、本人確認手段、申告利用目的、過去凍結口座などをノードとし、相互関係をネットワークとして扱う。これにより、同一端末の使い回し、急激なファンアウト、短命な受け皿クラスターなどを捉えやすくなる。

3. **ShinkaEvolve で説明可能な検知プログラムを進化させる。**  
   静的な分類器だけでなく、グラフルール、時系列ルール、敷居値、エスカレーション方針を含む検知プログラムを探索する。出力は allow / 追加確認 / 一時保留 / アナリスト送付 / 凍結 のような監査可能なロジックを目指す。

4. **攻撃者が適応するベンチマークを作る。**  
   フィッシング起点のアカウント乗っ取り、被害者自身に IB 口座を作らせる手口、同名口座を使った中継、受け皿口座への高速送金、端末・アクセス環境の変更などを含むシミュレーションを作る。主な研究問いは、人手ルールよりも進化したプログラムの方がドリフト下で有効性を保てるかどうかである。

5. **モデル精度ではなく銀行の成果で最適化する。**  
   目的関数は、防止できた金額、早期遮断、頑健性を評価しつつ、誤検知、アナリスト負荷、顧客摩擦、不必要な凍結を罰する多目的最適化にする。

6. **初期導入は human-in-the-loop にする。**  
   最初から完全自動ブロックを目指す必要はない。まずは、新しいシナリオ候補の提案、受け皿クラスタの可視化、フラグ理由の説明を行うアナリスト支援システムとして導入する方が現実的である。

## 拡張性

日本のオンラインバンキング詐欺に対して有効性が示せれば、同じ枠組みを地銀、信金、カード、証券、さらには口座乗っ取りや暗号資産・送金サービス向けの周辺対策にも拡張しやすい。
